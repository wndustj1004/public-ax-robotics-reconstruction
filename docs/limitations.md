# 한계

## 1. 이 저장소 자체의 한계

| 항목 | 상태 |
|---|---|
| 원본 코드 | **없음.** 당시 최종 통합 코드는 회수되지 않았다 |
| 학습된 가중치 | 없음 |
| 데이터셋 | 없음. 스키마와 폴더 구조만 있다 |
| 실물 하드웨어 검증 | **미수행.** Raspberry Pi 5 · AMR · 매니퓰레이터로 실행한 적 없다 |
| 실제 추론 경로 검증 | **미수행.** `ultralytics` 를 설치해 돌려 보지 않았다 |
| 검증한 범위 | 설정 로드, 대응표 조회, 다수결, 상태 전이, 실패 처리 — 전부 simulation |

## 2. 당시 프로젝트의 한계

| 항목 | 내용 |
|---|---|
| 성능 지표 | **없음.** 반복 정량 측정을 수행하지 않았다. 정확도·성공률·지연시간을 주장하지 않는다 |
| 일반화 | 단일 환경에서 촬영한 인쇄 이미지 모형이다. 조명·배경 변화에 대한 검증이 없다 |
| 완전 자동화 | 아니다. ROBOT FIX 루트는 사람이 정상 플레이트를 투입하는 개입을 설계에 포함한다 |
| 대상 식별 | 실물 플레이트 ID를 읽지 못한다. 판정 결과와 실물을 확실히 묶지 못한다 |
| 주행 정밀도 | 일부 구간이 시간 기반 개루프 이동이라 오차가 누적된다 |
| 로그 | 스키마는 정의했으나 실제 생성된 로그 파일이 보존되어 있지 않다 |
| 적용 범위 | 교육용 하드웨어를 사용한 개념검증이다. GMP 밸리데이션·LIMS 연동은 범위 밖이다 |
| 전문 판독 | 범위 밖이다. 이 시스템은 미생물학적 판정을 하지 않는다 |

## 3. 알려진 미해결 사항

- `configs/classes.yaml` 의 클래스 문자열은 **확인되지 않은 값**이다.
  기획서·발표자료는 `robotfix`/`humanfix`, 폴더에 남은 이전 세대 노트북은
  `robot_fix`/`human_fix` 로 되어 있다. 최종본을 확인할 수 없다.
- `min_confidence: 0.70` 은 이전 세대 노트북의 값이다. 최종본의 값은 확인 불가.
- 규제 조문(노출 시간 제한)의 조항 번호와 발효일은 **공식 원문 재확인이 필요하다.**
- 상용 장비 성능 수치(처리량, 개입 감소율)는 제조사 공개자료를 인용한 것이며
  원문과 직접 대조하지 않았다.
