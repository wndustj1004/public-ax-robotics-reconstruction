## 이 저장소로 확인할 수 있는 것 (현재 시점의 역량)

| 주장 | 산출물 | 확인 위치 | 한계 |
|---|---|---|---|
| 시나리오를 요구사항으로 옮길 수 있다 | 시나리오 문서 → 대응표·상태표 | `docs/scenario.md`, `configs/classes.yaml` | 당시 문서 기반. 코드와 대조 검증은 불가 |
| 판정을 조치로 바꾸는 계층을 설계·구현할 수 있다 | 대응표 조회 정책 | `src/decision_policy.py` | simulation 으로만 검증 |
| 상태 전이와 안전 정지를 설계할 수 있다 | 전이표 + 실패 수렴 | `src/state_machine.py` | 동일 |
| 하드웨어 없이 검증 가능한 부분을 분리할 수 있다 | 프로토콜 경계 | `src/interfaces.py`, `src/simulation.py` | 실물 구현 없음 |
| 테스트를 작성할 수 있다 | 32개 테스트 (전부 통과) | `tests/` | 순수 로직만. 하드웨어·모델 미포함 |
| 확인된 것과 아닌 것을 구분해 문서화할 수 있다 | 고지·한계 문서 | `RECONSTRUCTION_NOTICE.md`, `docs/limitations.md` | — |
| AI 생성 코드를 검토·통제할 수 있다 | 역할 구분 고지 | `NOTICE.md` | — |
