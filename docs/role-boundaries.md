# 역할 경계

프로젝트는 3인 팀이었다. 팀원은 이름 없이 담당 영역으로만 적는다.
아래 구분은 저장소 작성자가 직접 확정한 것이며, 근거 파일이 있는 항목은 함께 적었다.

## A. 저장소 작성자가 당시 주도한 것

| 항목 | 근거 |
|---|---|
| 산업 배경·규제 조사 (EM 공정, GMP Annex 1) | 기획서 2.1, 산업 조사 메모 |
| 상용 자동화 3종 벤치마킹 | 기획서 2.1 |
| 문제 정의 — "고정형 장비 사이의 공백" | 기획서 2.1, 발표 대본 |
| **3클래스 조치등급 설계 (조치에서 역산)** | 기획서 [표3], 발표 대본 |
| **YOLO 학습 및 엣지 보드 탑재** | 발표 대본 |
| 기획서 집필 (7장 구성) | 기획서 PDF |
| 발표자료 제작 및 발표 | 발표자료 HTML, 대본 |

## B. 공동으로 한 것

| 항목 | 그 안에서 작성자가 맡은 부분 |
|---|---|
| 데이터셋 구축 | 표준 이미지 설계, 촬영 조건 수립. 라벨링·증강은 분담 |
| ArUco 정차 조건 변경 | **사양 제안**(거리 조건으로 바꾸자). 코드는 팀원 |
| 카메라 캘리브레이션 | 체커보드 촬영·산출을 팀이 함께 수행 |
| HMI 상태 표시 | **사양 제안**(대기 구간 화면 유지, 로그 항목). 코드는 팀원 |
| 완료 검증 단계 | **사양 제안**(재인식으로 완료 판정, 미검출 시 타임아웃) |
| 주행 시나리오 구체화 | 시나리오 내용 논의. **코드 작성은 미참여** |
| AI 협업 인수인계 문서 | 공동 작성 |

## C. 팀원이 담당한 것 — 이 저장소에 없다

| 항목 |
|---|
| 라인트레이싱(IR 3채널) 및 교차로 판정 |
| 주행 튜닝 (속도·시간 상수 실측 보정) |
| 이기종 로봇 간 파일 핸드셰이크 (상태·명령 파일 교환) |
| 통합 실행 루프 및 예외 처리 |
| 모방학습(ACT) 데이터 수집 |
| ACT 정책 학습 및 추론 연동 |

**위 항목은 저장소 작성자의 코딩 역량 근거로 쓰지 않는다.**
시스템을 설명할 때는 언급하되 담당이 팀원이었음을 함께 적는다.
이 저장소의 `src/interfaces.py` 는 C 영역을 **경계면으로만** 남겨 둔 것이며,
그 뒤의 실물 구현은 들어 있지 않다.
